# Система управления личными финансами

Консольное приложение на Java для учёта доходов, расходов и бюджетов. У каждого пользователя свой кошелёк с категориями, операциями и лимитами.

## Сборка и запуск

Нужны JDK 21 и Apache Maven 3.9.

```text
mvn verify
java -jar target/personal-finance.jar
```

По умолчанию приложение хранит данные в каталоге `data/` относительно текущей рабочей папки. Для самостоятельного примера запустите приложение с новым каталогом данных.

```text
java -jar target/personal-finance.jar --data-dir target/demo-data
```

Если в пути есть пробелы, заключите его в кавычки.

## Команды

Введите команду отдельной строкой и отвечайте на приглашения по одному значению за строку. При регистрации укажите непустой пароль. Допустимые логины соответствуют шаблону `[A-Za-z0-9_-]{1,32}`. Сумма или лимит должны быть больше нуля. Дробную часть можно отделить точкой или запятой, максимум два знака после разделителя. Даты вводятся в формате `yyyy-MM-dd`. Пустая дата операции означает сегодняшний день.

| Команда | Что ввести в ответ на приглашения |
| --- | --- |
| `help` | Справка с примерами. |
| `register`, `login` | Логин, затем пароль. После регистрации выполните `login`. |
| `logout`, `exit` | Выйти из аккаунта или закрыть приложение. |
| `categories` | Показать список категорий. |
| `category add` | Имя новой категории. |
| `category rename` | Текущее имя, затем новое. Операции и лимит переходят на новое имя. |
| `income`, `expense` | Существующая категория, сумма, дата. |
| `budget` | Существующая категория, лимит. Повторная команда обновляет лимит. |
| `report` | Имена категорий по одному в строке, пустая строка завершает список. Затем начальная и конечная даты. |
| `report file` | Те же параметры, затем путь к новому файлу вне каталога данных. |
| `export` | Путь к новому CSV-файлу вне каталога данных. |
| `import` | Путь к CSV-файлу. После проверки файла введите `да`, чтобы заменить текущий кошелёк. |
| `transfer` | Логин получателя, сумма, дата. Нужен зарегистрированный получатель и достаточный остаток у отправителя. Перевод учитывается в категории «Переводы» как расход отправителя и доход получателя. |

Для отчёта сразу нажмите Enter на запросе категории, чтобы включить все категории. Каждую границу периода можно оставить пустой. Указанные даты включаются в период. Отчёт показывает доходы, расходы и баланс выбранных операций. Отдельный блок показывает все установленные бюджеты. Остаток каждого бюджета рассчитывается по всей истории расходов соответствующей категории.

При расходовании от 80% бюджета приложение предупреждает о приближении к лимиту, при расходах свыше 100% сообщает о перерасходе. После операции, перевода или импорта приложение также сообщает о нулевом или отрицательном балансе.

В выбранных категориях доходы составят `60000.00`, расходы — `800.00`. Чтобы сохранить отчёт, используйте `report file` с теми же параметрами и укажите новый файл, например `target/demo-report.txt`.

Относительные пути отсчитываются от рабочей папки. Каталог для нового файла должен существовать.

Чтобы сделать копию кошелька, введите `export` и новый путь `target/demo-wallet.csv`. Этот файл можно загрузить командой `import`, указав его путь и подтвердив замену текущего кошелька.

Для проверки перевода создайте отдельного получателя и отправьте ему `100.00` из кошелька `demo`.

```text

demo

2026-09-01
```

После перевода баланс `demo` составит `54600.00`. Введите `exit`, снова запустите приложение с `--data-dir target/demo-data` и войдите в `recipient`. Отчёт покажет доход и баланс `100.00`.

## Архитектура и хранение данных

- `core` содержит модель `Wallet`, операции и отчёты. `FinanceService` управляет сессией и операциями с кошельками через интерфейсы хранения. Денежные расчёты используют `BigDecimal`.
- `infra` реализует интерфейсы хранения с помощью CSV. В `accounts.csv` хранятся логины, индивидуальные соли и хеши паролей PBKDF2. `wallets.csv` хранит снимок всех кошельков и обновляется атомарной заменой. CSV для импорта и экспорта содержит данные одного кошелька.
- `cli` читает команды и параметры, проверяет ввод и форматирует результаты. Точка входа `Main` связывает консоль, сервис и файловое хранилище.

При входе приложение загружает кошелёк пользователя, а при выходе из аккаунта или приложения сохраняет состояние. В течение работы открытые кошельки находятся в памяти. На один каталог данных допускается один работающий процесс. Приложение удерживает блокировку через файл `finance.lock`.

## Проверки

`mvn verify` собирает исполняемый JAR и запускает тесты JUnit. Они проверяют финансовые расчёты, фильтрацию и лимиты, а также пользовательские сценарии с сохранением данных в файлы. Workflow GitHub Actions запускает `mvn --batch-mode --no-transfer-progress verify` на Java 21 при push и pull request.
